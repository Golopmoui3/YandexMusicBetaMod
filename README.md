# 📱 Яндекс Музыка (Android) — мод без Плюса

Мобильная версия мода: пропатченный APK Яндекс Музыки для Android. Все правки внесены прямо в smali-код приложения — без root, Magisk и прокси.

## ❤️ Преимущества

✔️ Работает без Плюса

🎧 Запрашивается максимальное качество звука (LOSSLESS / `high_quality`)

🚫 Промо-баннеры убраны

💛 Блоки «поддержать артиста» убраны

👁️ Стрим-аналитика (`log.strm.yandex.ru`) не покидает устройство

## 📲 Установка

1. Скачайте APK со страницы [Releases](../../releases/latest) — файл `YandexMusic-mod.apk` в ассетах последнего релиза.
2. Удалите оригинальное приложение Яндекс Музыки.
3. Разрешите установку из неизвестных источников.
4. Установите APK и войдите в аккаунт.

## 🔧 Что пропатчено

| # | Функция | Как реализовано |
|---|---------|-----------------|
| 1 | Плюс-статус | В DTO ответа `account/about` геттеры `hasPlus` и `hasMusicSubscription` всегда возвращают `true`. Патч сделан через геттеры, а не конструктор: Gson парсит DTO в обход конструктора |
| 2 | Максимальное качество | Оба маппера «настройки → качество плеера» переписаны на безусловный возврат LOSSLESS (`high_quality`) — мобильный аналог auto-best-quality |
| 3 | Промо-баннеры | Геттер DTO блока `promotions` всегда возвращает пустой список |
| 4 | Донейты | Геттер DTO блока `donations` всегда возвращает пустой список |
| 5 | Аналитика | Все три эндпоинта `log.strm.yandex.ru` (`/log`, `/perf`, `/v2/perf`) перенаправлены на `127.0.0.1:9` — батчи событий мгновенно отбрасываются и не уходят на серверы |

UAAS-конфиг плеера (`frontend.vh.yandex.ru/uaas`) сознательно не тронут — он нужен для воспроизведения.

## 💀 Ограничения

- Качество физически отдаёт сервер: клиент лишь запрашивает `high_quality`. Если сервер откажет аккаунту без Плюса в выдаче — трек может не воспроизвестись.
- AppMetrica не вырезана — на smali-уровне это слишком рискованно для старта приложения. Отрезана только стрим-аналитика плеера.
- Серверный конфиг теоретически может переопределить URL лог-эндпоинтов — обход блокировки.
- Региональные ограничения те же, что у оригинального приложения.

## 📁 Сурсы

- [patches/](patches) — шесть пропатченных smali-файлов. Структура папки повторяет дерево декомпилированного apktool-проекта, так что патчи накладываются простым копированием поверх декодированных исходников.
- [build.sh](build.sh) — скрипт полной сборки: merge сплитов → декомпиляция → наложение патчей → сборка → подпись. Пути к инструментам и keystore задаются переменными окружения.

## 🛠 Как собрано

1. APK-сплиты Яндекса → merge в один APK (APKEditor)
2. Декомпиляция apktool (~54 000 smali-файлов)
3. Наложение патчей из `patches/` (таблица выше)
4. Сборка apktool → zipalign + подпись uber-apk-signer (v1+v2+v3)

Всё это автоматизирует `./build.sh`; готовый APK лежит на странице [Releases](../../releases).
